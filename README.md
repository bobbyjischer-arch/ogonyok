# Огонёк — привычки и занятия в Telegram

Телеграм-бот и мини-апп: серии («огоньки») по полезным привычкам, счётчики
без срывов по вредным, фокус-таймер, учёт занятий с таймером и статистика.

Работает на Cloudflare Workers + D1: бесплатно, всегда онлайн, без своего
сервера и без туннеля с домашнего компьютера.

Живая версия — [@FernandnessHabitbot](https://t.me/FernandnessHabitbot).

## Что умеет

### Бот

| Команда | Что делает |
| --- | --- |
| `/start` | Выбор занятия; если занятие уже идёт — показывает его состояние |
| `/list` | Последние 10 занятий с временем и длительностью |
| `/app` | Кнопка мини-аппа |
| `/cancel` | Отменить ожидание отметки |
| `/admin` | Панель куратора (в публичном режиме её нет, см. ниже) |

Привычку можно завести прямо из переписки: кнопка → название → бот сам
подберёт иконку. Отметить день — тоже кнопкой под сообщением.

### Мини-апп

Пять вкладок:

- **Занятия** — идущее занятие с посекундным таймером, старт в один тап,
  сводка за сегодня, история с фильтром по типу, правка времени начала и
  конца, удаление.
- **Привычки** — два режима в одном экране:
  - *поддержание* («Полезные») — ежедневная отметка и серия огоньков как в
    Duolingo. Можно задать дни недели: в незапланированный день серия не
    рвётся, поэтому «спорт по пн/ср/пт» держит огонёк честно. Пропущенный день
    закрывается тапом по сетке за последние 30 дней — «сделал, но забыл
    нажать» бывает у всех. Серия и рекорд считаются из полной истории отметок
    на клиенте, поэтому рассинхронизироваться с фактами им негде.
  - *отказ* («Отказ») — счётчики без срывов, этапы (час, день, неделя,
    месяц…), сэкономленные деньги, «избежали» в штуках, рекорды.
- **Фокус** — таймер на 2/5/10/15 минут с дыханием по квадрату, привязывается
  к привычке.
- **Статистика** — всё вместе.
- **Профиль** — оформление, язык (ru/en), валюта.

**Оформление** устроено как в Telegram: тема (как в клиенте / светлая /
тёмная) и палитра — системная, тёплая (песок и терракота днём, обожжённое
дерево ночью) или взятая прямо из темы Telegram, включая пользовательские.
Выбор хранится на сервере, поэтому переезжает между устройствами, и дублируется
в localStorage — иначе приложение успевало моргнуть чужими цветами до ответа
сервера. Цвета живут в `miniapp/src/lib/theme.ts`: добавить палитру — это
дописать туда одну запись.

## Два режима

Один и тот же код, разница — переменная `PUBLIC_MODE` в `wrangler.toml`.
Ветвлений на сборке нет: бандл мини-аппа буквально один и тот же файл, а режим
приезжает с сервера полем `isPublic` в состоянии.

| | Публичный (`"1"`) | С куратором (`"0"`) |
| --- | --- | --- |
| Кого пускает | кого угодно | только `ALLOWED_USERS` |
| Отметки куратору | не уходят | уходят в личку, он отвечает реплаем |
| «Начал / завершил» куратору | не уходят | уходят |
| Сова на ветке | нет | есть |
| Панель куратора и `/admin` | только если задан `CURATOR_ID` | есть |
| Приветствие в `/start` | «это твой трекер» | «отмечайся, куратор видит» |

Режим с куратором — это «я и тренер» или маленькая группа: любое сообщение во
время идущего занятия становится отметкой и копией уходит куратору (текст,
голосовое, кружок, фото), а его реплай доставляется автору. В публичном режиме
такого нет намеренно — иначе чужой личный чат завалило бы кружками незнакомых
людей.

Совы в публичном режиме тоже нет намеренно: реплики она берёт из занятий с
куратором, а без него питомец говорил бы мимо.

Куратор проверяется **отдельно**, а не подмешивается в `ALLOWED_USERS`: если
дописывать его в список, список никогда не бывает пустым, и «пустая строка =
открыто всем» перестаёт работать. На этом публичная версия один раз и
споткнулась — не пускала никого, кроме куратора.

## Как устроено

```
wrangler.toml          конфиг воркера: статика, база, cron, переменные
migrations/            схема D1
worker/src/
  index.ts             роутинг: вебхук, /api, /setup, статика; cron
  bot.ts               сценарии бота, клавиатуры, панель куратора
  api.ts               REST для мини-аппа
  checkins.ts          общий путь отметки — им пользуются и бот, и приложение
  db.ts                весь SQL
  auth.ts              проверка подписи initData на WebCrypto
  tg.ts                клиент Bot API на fetch, без библиотек
  activities.ts        типы занятий
  env.ts, util.ts      привязки, доступы, время
miniapp/               React + Vite + Tailwind + @telegram-apps/sdk
scripts/smoke.py       интеграционный прогон режима с куратором
scripts/smoke_public.py то же для публичного режима
```

Мини-апп, API и вебхук живут на одном origin: поэтому кнопка `web_app`
открывает тот же адрес, откуда пришла страница, и CORS в проекте нет вообще.

Каждая мутация в API возвращает **полное свежее состояние**. Клиенту нечего
сливать вручную, и вкладки не могут разъехаться между собой.

Библиотек для Telegram нет ни на сервере, ни в боте: Bot API — это обычный
`fetch`, а подпись `initData` проверяется через WebCrypto. На Workers так
проще, чем тащить aiogram-подобный слой.

## Развернуть у себя

Нужен только бесплатный аккаунт Cloudflare и токен бота от @BotFather.

```bash
npm run install:all

npx wrangler login          # или CLOUDFLARE_API_TOKEN, см. ниже
npm run db:create           # напечатает database_id
```

Полученный `database_id` вставь в `wrangler.toml` вместо
`REPLACE_WITH_D1_DATABASE_ID`. Дальше:

```bash
npm run db:migrate          # схема на удалённой базе

# придумать секрет вебхука (любая случайная строка):
node -e "console.log(crypto.randomUUID().replace(/-/g,''))"

npm run secrets             # спросит BOT_TOKEN, потом WEBHOOK_SECRET
npm run deploy              # соберёт мини-апп и задеплоит
```

Деплой напечатает адрес вида `https://ogonyok.<твой>.workers.dev`.
Последний шаг — один раз открыть в браузере:

```
https://ogonyok.<твой>.workers.dev/setup?secret=<WEBHOOK_SECRET>
```

Этот адрес ставит вебхук, список команд и кнопку меню рядом с полем ввода.
В ответ придёт JSON с именем бота и состоянием вебхука. После этого пиши боту
`/start`. Повторять шаг нужно, только если сменился адрес воркера или токен
бота — деплой вебхук не сбрасывает.

Если `wrangler login` не проходит (браузер возвращается на `localhost:8976`,
а колбэк не доезжает — так бывает), вход делается токеном:

```bash
export CLOUDFLARE_API_TOKEN=...
export CLOUDFLARE_ACCOUNT_ID=...
```

Токену нужны права шаблона *Edit Cloudflare Workers* **плюс** вручную
добавленное **Account · D1 · Edit** — без него `d1 create` падает с
`Authentication error [code: 10000]`.

### Настройки

`wrangler.toml`, блок `[vars]`:

- `PUBLIC_MODE` — `"1"` публичный режим, `"0"` режим с куратором.
- `CURATOR_ID` — кому уходят отметки и у кого работает `/admin`. Пусто =
  куратора нет. Свой id узнать у @userinfobot.
- `ALLOWED_USERS` — список id через запятую; куратор проходит и без него.
  Пустая строка открывает бота всем.
- `CHANNEL_URL` — необязательная ссылка на канал в профиле приложения.
- `APP_NAME` — заголовок, который видит пользователь.

Секреты (`BOT_TOKEN`, `WEBHOOK_SECRET`) задаются через `npm run secrets` и
переживают деплой. `[vars]` применяются при следующем `npm run deploy`.

Режим с куратором вынесен в окружение `[env.curated]`: это отдельный воркер,
отдельный бот и отдельная база, а переменные и привязки окружениями не
наследуются. Команды к нему — с суффиксом `:curated` (`npm run deploy:curated`,
`logs:curated`, `db:console:curated`). Без `--env curated` wrangler базу
`tracker-curated` не находит вовсе: она объявлена внутри окружения.

## Локальная разработка

```bash
npm run db:migrate:local         # схема в локальную базу
cp .dev.vars.example .dev.vars   # положить туда токен и секрет
npm run dev                      # соберёт мини-апп и поднимет воркер на :8787
```

Вебхук локально Telegram не достанет, поэтому бота гоняй на задеплоенной
версии, а локально — API и интерфейс.

Интерфейс без Telegram вообще:

```bash
npm --prefix miniapp run dev
# открыть http://localhost:5173/?preview=1
```

`?preview=1` работает против локального мока (`miniapp/src/lib/mock.ts`) —
данные ненастоящие, зато видно всю вёрстку и все состояния.

## Тесты

Настоящий воркер поверх настоящей локальной D1, без моков.

```bash
npm run db:migrate:local             # иначе всё падает в 500
npm run dev                          # в одном терминале
python scripts/smoke_public.py       # в другом
```

28 проверок публичного режима: что человек с улицы заходит и заводит
привычки, что чужого он не видит и не удаляет, что панель куратора ему
закрыта, что подпись `initData` проверяется (валидная, подделанная,
протухшая), и что привычка заводится и отмечается прямо из переписки.

Режим с куратором — отдельным прогоном, у него своё окружение:

```bash
npm run db:migrate:curated:local
npm run dev:curated                  # в одном терминале
python scripts/smoke.py              # в другом
```

71 проверка: занятия, отметки, привычки со срывами, огоньки и расписание
дней, фокус, настройки, оформление, права куратора и правка им чужих событий,
вебхук с секретом и без, отдача статики и SPA-фолбэк.

id в `scripts/smoke.py` совпадают с `[env.curated.vars]` в `wrangler.toml` —
они выдуманные, и менять их надо в обоих местах сразу. `smoke_public.py` id
куратора читает из конфига сам и пропускает проверки панели, если `CURATOR_ID`
пуст.

Оба прогона идемпотентны — можно запускать по кругу; и оба отказываются
работать по неместному адресу, потому что пишут в базу. Порт `:8787` у обоих
один, поэтому одновременно их не поднять.

## Обслуживание

```bash
npm run logs                                    # живые логи воркера
npm run db:console "select * from activities limit 5"
npm run check                                   # сборка без деплоя
npm run typecheck                               # типы воркера
```

Раз в час (`:23`) cron закрывает занятия, которые забыли завершить: если
занятие висит открытым больше 12 часов, оно закрывается задним числом и
пользователю приходит сообщение. Иначе одно забытое занятие навсегда
оставалось бы «идущим» и портило всю статистику.

## Про бесплатный тариф

Бесплатный тариф Workers — **не пробный период**. В доках он описан как то,
что есть у аккаунта по умолчанию («By default, users have access to the
Workers Free plan»), рядом с платным как постоянная альтернатива; ни срока, ни
даты окончания нигде не указано. Карту привязывать не требуется. Риск не в
том, что тариф кончится по времени, а в том, что Cloudflare когда-нибудь
поменяет лимиты — но данные лежат в D1, и увезти их можно в любой момент.

Проверено по докам Cloudflare на 2 августа 2026:

- **Воркер** — 100 000 запросов в сутки (сброс в полночь UTC), 10 мс CPU на
  вызов, 50 подзапросов на запрос, 128 МБ памяти. Лимит общий на аккаунт.
- **Статика мини-аппа** — «Requests to static assets are free and unlimited»:
  файлы отдаются мимо воркера и лимит не тратят. Через воркер идут только
  `/api/*`, `/tg/*`, `/setup` и `/healthz`.
- **D1** — 5 млн прочитанных строк и 100 000 записанных в сутки, 5 ГБ на
  аккаунт (500 МБ на базу), до 50 запросов к базе на один вызов воркера,
  откат состояния (Time Travel) на 7 дней.
- **Cron** — на бесплатном тарифе есть, до 5 расписаний на аккаунт.

Расход: открытие приложения — один запрос, любое действие — один, апдейт
бота — один. Каждый такой запрос вдобавок пишет одну строку в `users` (там
обновляется `last_seen_at`), так что запросы к воркеру и записи в D1
расходуются почти один к одному и упираются в свои 100 000 примерно
одновременно. Активный человек тратит за день пару десятков запросов — то
есть бесплатного тарифа хватит на тысячи людей.

Один нюанс: пути с `run_worker_first` при исчерпании лимита отдают 429, а не
откатываются на статику. То есть при (недостижимом) переполнении перестанет
работать API, но страница продолжит открываться.
